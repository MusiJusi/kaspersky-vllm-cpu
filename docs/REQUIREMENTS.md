# Требования и критерии приёмки

Источник: предоставленное задание команды исследования технологий машинного
обучения. Оригинал остаётся локально и не включается в Git.

Все пункты ниже пока ожидают реализации и проверки.

## Обязательная часть

| Требование | Чем подтверждаем |
| --- | --- |
| Полноценный Kubernetes или Minikube | Успешный деплой и запрос к сервису в кластере |
| Открытая instruct-модель, подходящая по ресурсам | Указаны model ID, revision и выделенные ресурсы; получен ответ |
| Инференс строго на CPU | Использована CPU-сборка vLLM, в окружении сервиса подтверждён CPU backend; GPU не выделяется |
| vLLM версии 0.27.0 или выше | Версия зафиксирована и проверена внутри собранного образа |
| Собственный Dockerfile | Сборка по инструкции из репозитория |
| Процесс запускается не от root | Проверка UID в контейнере и securityContext в Kubernetes |
| Полный pinned requirements.txt | Все прямые и транзитивные зависимости зафиксированы; установка и проверка согласованности успешны |
| Кастомизация логирования vLLM | Код или конфигурация в репозитории; проверка stdout/stderr |
| Промпты и ответы не попадают в логи | Проверки успешного, streaming и ошибочного запроса с контрольными строками |
| Факт обращения логируется | В логах есть запись с безопасными метаданными запроса |
| Модель хранится на PVC | Манифест PVC и подтверждённое сохранение после пересоздания Pod |
| Первая загрузка модели автоматическая | Запуск с пустым PVC скачивает нужные файлы |
| Повторный запуск без обращения к сети за моделью | Запуск с готовым PVC при недоступном Hugging Face успешен |
| HF-токен передаётся через Secret | Secret подключён к загрузчику; реальный токен отсутствует в Git |
| API Bearer-токен передаётся через Secret | Генерация разрешена с токеном и отклоняется без токена либо с неверным |
| Параметры vLLM управляются через ConfigMap | Параметры меняются после обновления конфигурации и перезапуска, образ остаётся прежним |
| README с локальным запуском | Инструкция пройдена с чистого состояния |
| Ссылка на репозиторий | Проверяющие имеют доступ; файл со ссылкой назван и загружен по инструкции |

## Бонусы

| Бонус | Чем подтверждаем |
| --- | --- |
| Kustomize | Конфигурация собирается и применяется через `kubectl apply -k` |
| Отдельный лёгкий rootless initContainer | Отдельный Dockerfile; UID не равен 0; загрузка выполняется перед стартом сервиса |
| Нагрузочные тесты | Воспроизводимый скрипт, короткие и длинные промпты, TTFT, latency, throughput |
| Анализ производительности | Обоснование параметров для большого числа коротких запросов и меньшего числа запросов с большим контекстом |

## Что фиксируем в результатах

Версии vLLM, Python и образов, model ID и revision, выделенные CPU и RAM,
dtype, ограничения контекста, параметры тестов и фактические метрики.
Запланированное поведение и непроведённые проверки не обозначаются как успешные.
